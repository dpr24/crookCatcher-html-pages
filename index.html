Executive Summary & Purpose

Crook Catcher functions as an autonomous, silent mobile security sentinel. Mobile theft and unauthorized snooping usually occur when a phone is left unattended or stolen. Crook Catcher immediately captures high-definition photos, front/back video with ambient audio, exact GPS coordinates, and device telemetry when an unauthorized entity attempts to guess the screen PIN, pattern, or password.

Core Mission Objective
Ensure that evidence (facial captures, GPS coordinates, and audio) is transmitted off-device instantaneously so that even if the physical phone is damaged, turned off, or factory reset, the owner retains definitive intruder evidence in their inbox and cloud storage.

Boot Persistence (`RECEIVE_BOOT_COMPLETED`)

Crook Catcher registers a custom Android BroadcastReceiver for boot events. As soon as the device reboots, security services restart automatically in low-power idle mode.

Foreground Watchdog Service

Maintains process memory priority using an official Android FOREGROUND_SERVICE with low-priority notification channel, protecting the app from OS killer daemons.

Device Admin Access & Break-in Detection

Device Admin access (DevicePolicyManager) is the mandatory engine required to intercept lock screen password attempts and detect break-ins.

Why Device Admin Permission is Essential:
  • Break-in Detection: Intercepts onPasswordFailed() and onPasswordSucceeded() to verify if an intruder successfully unlocked the device after failed attempts.
  • Uninstall Protection: Prevents unauthorized uninstallation by thieves directly from system app settings.
  • Auto-Re-enable: Restores security monitoring hooks automatically post-device reboot.

Native Kotlin Listener (`AdminReceiver.kt`)

AdminReceiver.kt 
class AdminReceiver : DeviceAdminReceiver() {
    override fun onPasswordFailed(context: Context, intent: Intent) {
        super.onPasswordFailed(context, intent)
        // Trigger silent photo/video & GPS capture
        BackgroundCaptureService.startCapture(context, isBreakIn = true)
    }

    override fun onPasswordSucceeded(context: Context, intent: Intent) {
        super.onPasswordSucceeded(context, intent)
        // Check if intruder succeeded after failed attempts (Break-in alert)
        BreakInDetector.checkBreakInState(context)
    }
}

Failure Modes & Edge Cases (When It Fails)

Failure Scenario Root Cause Impact Mitigation Strategy
Instant Hard Power-Off Thief immediately holds power button down upon failing PIN. Camera/GPS service interrupted before upload completes. Sub-800ms fast photo grab + immediate non-volatile disk caching for auto-dispatch on next boot.
Offline / No Network No SIM inserted, Wi-Fi disconnected, or Airplane mode active. Email alert and Google Drive cloud uploads fail instantly. WorkManager persistent queue with exponential retry backoff; flushes data upon network reconnect.
Camera Hardware Lock Camera resource occupied by system or another background app. CameraInUseException thrown during capture. Automatic 500ms fallback retry loop; falls back to audio recording + location payload if camera remains locked.
OEM Battery Killing Aggressive background task killers on Xiaomi MIUI, Samsung OneUI, Vivo. Background service killed after long screen-off idle time. Guided onboarding screen directing user to disable OEM battery optimization & enable Auto-Start.

Technical Implementation Difficulties

DeviceAdmin API Scope Deprecations

Google has tightened Android DeviceAdminReceiver scope. Intercepting ACTION_PASSWORD_FAILED requires explicit admin activation by the user during initial setup.

Background Camera Constraints (Android 10+)

Android 10+ restricts opening camera hardware from background services unless accompanied by a visible foreground service type (FOREGROUND_SERVICE_TYPE_CAMERA).

iOS Platform Lock Screen Blocker

Apple iOS sandbox does NOT expose lock screen failed unlock callbacks to third-party applications. Core lock screen intruder capture is Android exclusive.

Scoped Storage & Drive Token Refresh

Android 11+ Scoped Storage requires writing media to private app directories before streaming to Google Drive using background OAuth2 refresh tokens.

Future Issues, Risks & Mitigation Strategies

Google Play Policy Compliance Risk
Apps utilizing Device Admin, Camera, and Background Location face intensive automated and manual Play Store policy audits.

Risk Mitigation Plan

  • Transparent Prompts: Provide full-page video demonstrations during setup explaining why DeviceAdmin & Camera permissions are needed.
  • WorkManager Adaptation: Migrate long video captures into atomic 15-second chunks compatible with Android 15+ background execution limits.
  • Laravel Proxy Backup: Route cloud uploads through our central Laravel storage API to prevent client-side Google Drive API quota exhaustion.

Pros and Cons Analysis

System Advantages (PROS)

  • High Evidence Yield: Captures facial photos, ambient audio, video, and GPS location instantly upon unlock failure.
  • Cloud Data Survival: Off-device email & Google Drive backup ensures evidence is safe even if the phone is destroyed or wiped.
  • Clever Decoy Trickery: Fake Home Screen tricks intruders into entering dummy sessions while silently recording video.
  • Scalable Laravel Backend: Queue-driven email rendering handles concurrent alert bursts effortlessly.
  • Cross-Platform Base: Flutter codebase allows 85%+ shared logic between Android and companion web dashboards.

System Tradeoffs (CONS)

  • iOS Platform Restriction: Apple iOS sandbox prevents third-party apps from intercepting lock screen PIN failures (Android exclusive core).
  • Device Admin Policy Scrutiny: Risk of strict Google Play Store review rejections if permissions are not thoroughly justified.
  • OEM Background Killing: Requires guiding non-technical users to manually disable battery optimization on Xiaomi/Samsung phones.
  • Hardware Lock Conflicts: If another app holds active camera lock at attempt time, photo capture can face minor delay.
