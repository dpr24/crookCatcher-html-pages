  • UI Philosophy: Rich, highly configurable settings and evidence gallery.

Minimalist, stealth-focused utility designed for maximum battery conservation. Distinctive for hardware-level triggers like SIM card swaps and power-on alerts.

  • UI Philosophy: Ultra-minimal single-page setup; zero intrusive UI.
  • False-Alarm Guard: 10-second delay cancels alert if PIN entered correctly.

3. Cross-App Missing Features Deep-Dive

Competitive Asymmetry

Analysis of key capabilities present in one commercial market leader but absent in the other, explaining their operational trade-offs and security implications.

Features Present in CrookCatcher but MISSING in Lockwatch

  • Fake Home Screen Decoy Launcher: CrookCatcher presents a convincing dummy launcher interface to trick an intruder into believing they successfully unlocked the device. Lockwatch has zero decoy UI.
  • Loud Anti-Theft Panic Siren: CrookCatcher can blast a high-volume siren overriding silent mode to startle thieves in public. Lockwatch offers no audible alarms.
  • In-App Biometric App Lock: CrookCatcher protects its own settings and evidence gallery with biometric fingerprint/PIN authentication. Lockwatch has no dedicated app lock.
  • Disguised App Icon & Masquerading: CrookCatcher allows users to camouflage the launcher icon as a Calculator or Notes app. Lockwatch does not support icon swapping.
  • Multiple Alert Email Recipients (Up to 3): CrookCatcher PRO can broadcast alert emails to 3 emergency contacts simultaneously. Lockwatch is strictly limited to 1 recipient address.
  • Multi-Photo Rapid Burst (Up to 4 Shots): CrookCatcher captures up to 4 sequential front-camera photos to overcome blurry shots. Lockwatch captures only a single photo.
  • Personal Google Drive Cloud Backup: CrookCatcher uploads evidence directly into the user's personal Google Drive folder via OAuth2. Lockwatch has no cloud backup beyond email.

Features Present in Lockwatch but MISSING in CrookCatcher

  • SIM Card Change Detection & Emergency Alert: When a thief replaces the owner's SIM card, Lockwatch immediately grabs GPS coordinates and emails the owner with the new SIM card's phone number and IMSI identifier. CrookCatcher completely lacks SIM swap monitoring.
  • Power-On Location Alert (Pre-Unlock): Lockwatch intercepts the cold boot sequence (`LOCKED_BOOT_COMPLETED`) and sends a location alert as soon as the phone starts up, before any unlock attempt is made. CrookCatcher only triggers after a failed PIN attempt.
  • 10-Second False Alarm Grace Period: If the legitimate owner mistypes their PIN but enters the correct PIN within 10 seconds, Lockwatch automatically cancels and deletes the pending email alert. CrookCatcher fires immediately upon threshold breach.
  • 4+ Character Attempt Filter: Lockwatch actively ignores accidental single taps or partial inputs (< 4 PIN digits or < 4 pattern dots), preventing unintentional counter increments. CrookCatcher triggers on any OS failure callback.

5. Real-Life Security Threat Scenarios & Behavioral Walkthroughs

Field Operations
Scenario 1

The Public Transit Pickpocket

Threat Event: A commuter's phone is pickpocketed on a subway train. The thief attempts common PINs (1234, 0000) while sitting among passengers.
CrookCatcher: Takes 3–4 photos, activates decoy fake launcher, and blasts siren alarm if configured. Alerts sent via cloud relay.
Lockwatch: Silently takes 1 photo. Waits 10s. Since no correct PIN is entered, emails photo + GPS coordinates to owner.
Our Sample App: Fires 3 silent photos + 3s front video + 3s rear video. Directly dispatches email over TLS socket to 3 emergency contacts with GPS and battery level.
Scenario 2

Airport Baggage SIM-Swap

Threat Event: A stolen phone is immediately powered off and its SIM tray popped out to prevent tracking and bypass SMS 2FA codes.
CrookCatcher: Fails to detect SIM removal. Remains dormant until someone turns the phone on and attempts unlock.
Lockwatch: Optimal Defense: Broadcast receiver catches new SIM, sends GPS coordinates and the new SIM card's IMSI/phone # immediately.
Our Sample App: Requires porting Lockwatch's TelephonyManager.ACTION_SIM_CARD_STATE_CHANGED receiver into native Kotlin.
Scenario 3

The Desk Snooper / Colleague

Threat Event: An office colleague picks up a phone left on a desk, tries a pattern once, fails, and the owner returns and unlocks it 7 seconds later.
CrookCatcher: Fires photo immediately if threshold is 1. Sends false-alarm email to owner, creating awkward interpersonal tension.
Lockwatch: Optimal Defense: 10-second grace window intercepts the legitimate unlock and silently discards the pending alert email. Zero false alarm spam.
Our Sample App: Captured to local history. Implementing a 10s dispatch cancel timer in Kotlin will match Lockwatch's convenience.

1. Supabase (Managed Postgres BaaS)

Provides enterprise authentication, device token management, and PostgreSQL Row-Level Security (RLS). Users are cryptographically restricted to their own incident records, while the Client Admin Console accesses global analytics using service role keys.

2. Cloudflare R2 (Direct Pre-Signed Storage)

High-resolution 1080p photos and MP4 video clips bypass the API application server entirely. The mobile phone uploads directly via pre-signed HTTP PUT tickets with $0 egress bandwidth fees, keeping cloud costs under $4.00/month.

3. Turnkey Admin Console (Next.js / Filament)

Using Next.js 14 + Refine.dev or Laravel 11 + Filament v3 allows the development team to launch a full-featured subscription monitoring and user data management console in under 3 days with zero boilerplate.

Core Database Schema: Users, Subscriptions, Devices & Incidents (PostgreSQL) 

-- 1. Users Table (Core Identity & Role Management)
CREATE TABLE users (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    email VARCHAR(255) UNIQUE NOT NULL,
    full_name VARCHAR(255),
    role VARCHAR(50) DEFAULT 'user' CHECK (role IN ('user', 'support', 'admin', 'superadmin')),
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    is_active BOOLEAN DEFAULT TRUE
);

-- 2. Subscriptions Table (Commercial Entitlements & Google Play Sync)
CREATE TABLE subscriptions (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID REFERENCES users(id) ON DELETE CASCADE,
    provider VARCHAR(50) NOT NULL CHECK (provider IN ('google_play', 'stripe', 'revenuecat', 'manual_promo')),
    external_subscription_id VARCHAR(255),
    plan_tier VARCHAR(50) DEFAULT 'free' CHECK (plan_tier IN ('free', 'pro_monthly', 'pro_annual', 'pro_lifetime')),
    status VARCHAR(50) DEFAULT 'active' CHECK (status IN ('active', 'in_grace_period', 'cancelled', 'expired')),
    current_period_start TIMESTAMP WITH TIME ZONE,
    current_period_end TIMESTAMP WITH TIME ZONE,
    cancel_at_period_end BOOLEAN DEFAULT FALSE,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- 3. Devices Table (Fleet Registry & Device Admin State)
CREATE TABLE devices (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID REFERENCES users(id) ON DELETE CASCADE,
    device_uuid VARCHAR(255) UNIQUE NOT NULL,
    model VARCHAR(100),
    os_version VARCHAR(50),
    is_admin_active BOOLEAN DEFAULT FALSE,
    is_armed BOOLEAN DEFAULT TRUE,
    last_battery_level INT,
    last_heartbeat TIMESTAMP WITH TIME ZONE,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- 4. Incidents Table (Evidence & Cloud Object Keys)
CREATE TABLE incidents (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    device_id UUID REFERENCES devices(id) ON DELETE CASCADE,
    timestamp TIMESTAMP WITH TIME ZONE NOT NULL,
    latitude DOUBLE PRECISION,
    longitude DOUBLE PRECISION,
    address TEXT,
    battery_level INT,
    failed_attempt_count INT DEFAULT 1,
    photo_urls JSONB DEFAULT '[]'::jsonb,
    video_urls JSONB DEFAULT '[]'::jsonb,
    storage_bytes BIGINT DEFAULT 0,
    is_starred BOOLEAN DEFAULT FALSE,
    is_purged BOOLEAN DEFAULT FALSE,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);
